# CSV/TSV 変換 仕様

同じフォルダの `convert.ts` にある `convertDelimitedText` の挙動仕様。UI には依存しない
ロジックなので、React / Next.js / Vue / Nuxt のどれで使っても同じ振る舞いになる。
使い方は [README.md](README.md)、この仕様を確かめるテストは `convert.test.ts`。

## エントリポイント

```ts
convertDelimitedText(
  input: string,
  columns: ColumnSpec[],
  format: OutputFormat = "json",
): ConvertResult
```

- `input` … 貼り付けられた CSV / TSV テキスト（1 行目をヘッダとして扱う）。
- `columns` … 列定義。項目名・出力キー・扱い・文字数・追加バリデーションを指定する。
- `format` … 出力形式。`"json"`（既定）/ `"csv"` / `"tsv"`。

戻り値はどちらか:

```ts
type ConvertResult =
  | { ok: true; rows: Record<string, string>[]; output: string }
  | { ok: false; errors: ConvertError[] }
```

**エラーが 1 件でもあれば `ok: false` となり、変換結果（`output`）は返さない。**

## 型

### ColumnSpec

| フィールド  | 型                | 必須 | 説明                                                                   |
| ----------- | ----------------- | ---- | ---------------------------------------------------------------------- |
| `label`     | `string`          | ○    | 貼り付けデータのヘッダ行に現れる項目名（日本語）。                     |
| `key`       | `string`          | ○    | 変換後の JSON / CSV / TSV のキー。                                     |
| `usage`     | `ColumnUsage`     | ○    | 列の扱い（`"required"` / `"optional"` / `"unused"`）。                 |
| `minLength` | `number`          | —    | 最小文字数。空でない値にのみ適用。                                     |
| `maxLength` | `number`          | —    | 最大文字数。空でない値にのみ適用。                                     |
| `validate`  | `ColumnValidator` | —    | 追加バリデーション。空でない値にのみ適用。エラー理由か `null` を返す。 |

```ts
type ColumnUsage = "required" | "optional" | "unused"
type ColumnValidator = (value: string) => string | null
type OutputFormat = "json" | "csv" | "tsv"
```

`ColumnUsage` の意味:

- **`required`** … 必須。ヘッダにも各行の値にも存在が必要。
- **`optional`** … 省略可。列自体が無ければ出力を `""` で埋める。値が空でもよい。
- **`unused`** … 不要。入力にあっても**出力から項目ごと削る**。

### ConvertError

```ts
interface ConvertError {
  row: number | null // 貼り付けテキスト内の行番号（ヘッダ起因は null）
  label: string | null // 対象の項目名（列を特定できない場合は null）
  message: string // 表示用の日本語メッセージ（行番号・項目名込み）
}
```

### 定数

- `MAX_ERRORS = 10` … 返すエラー件数の上限。これを超えた分は打ち切る（UI は「10件以上」と表示）。

## 入力の解釈

1. 空白のみの入力なら「データがありません」エラーで即終了する。
2. それ以外は**生のテキストをそのままパース**し、**前後の空行（全セルが空白のみの行）だけ**を取り除く。
   行内の区切り文字は保持するため、末尾セルが空の TSV 行（例 `"…\t営業部\t"`）でも列数がずれない。
   （`input.trim()` で入力全体を trim すると、タブ区切りの末尾の空セルの区切りタブまで削れてしまうのを避けている。）
3. 区切り文字は、**最初の空でない行（ヘッダ）にタブがあれば TSV、なければ CSV**（カンマ）とする。
   Excel からのコピペは必ずタブ区切りなので、2 列 × 1 行のような小さな表でも確実に TSV と分かる。
   （以前は papaparse の自動判別に任せていたが、行が少ないと外れてヘッダ全体が 1 項目になることがあった。）
4. 引用符（`"`）で囲めば、値の中のカンマや改行は区切りとして扱わない（papaparse 準拠）。
5. 改行は LF / CRLF どちらでもよい。
6. 前後の空行を除いた**先頭行をヘッダ**（項目名の行）として列定義と突き合わせる。列の並び順は自由。

## トリム（前後空白の除去）

- ヘッダ・各セルとも、**値の前後の空白を取り除いてから**扱う。
- 除去対象は正規表現 `/^[\s　]+|[\s　]+$/g` — 半角スペース・タブ・改行などの `\s` に加えて、**全角スペース（`U+3000`）** を含む。
- **値の途中の空白は保持する**（例: `" 山 田 "` → `"山 田"`）。
- 前後空白しか無いセルはトリム後に空文字となり、**空値として扱う**（必須ならエラー、省略可なら `""`）。

## ヘッダ行の検証

ヘッダは次の順で検証し、**1 件でもエラーがあればデータ行に進まず打ち切る**（ヘッダが不正なままでは行の検証結果が信用できないため）。

| 条件                            | `label` | メッセージ例                                     |
| ------------------------------- | ------- | ------------------------------------------------ |
| 項目名が空                      | `null`  | `ヘッダ: 2列目の項目名が空です`                  |
| 列定義に無い項目名              | 当該名  | `ヘッダ: 「住所」は定義されていない項目です`     |
| 同じ項目名が重複                | 当該名  | `ヘッダ: 「氏名」が重複しています`               |
| `required` の項目がヘッダに無い | 当該名  | `ヘッダ: 必須項目「メールアドレス」がありません` |

## データ行の検証と変換

ヘッダの次の行から順に処理する。

- **空行は読み飛ばす**。ただし行番号は貼り付けテキストの行のまま数える（エラー表示の行番号がずれない）。
- 行の**列数がヘッダと違う**場合はその行をエラーにして次へ進む。
  - 不足: `2行目: 項目が不足しています（3列必要ですが2列です）`
  - 過多: `2行目: 項目が多すぎます（2列必要ですが3列です）`
- 各セルは `usage !== "unused"` の列について、**列定義の順**で検証する。1 セルにつき出すエラーは最大 1 件で、優先順位は次のとおり:

  1. **必須チェック**（値が空）: `required` なら `2行目: 「氏名」は必須です`。`optional` は空でも可。
  2. **文字数チェック**（値が空でないとき）:
     - 超過: `2行目: 「氏名」は5文字以内で入力してください（現在9文字）`
     - 不足: `2行目: 「氏名」は2文字以上で入力してください（現在1文字）`
     - 文字数は**コードポイント数**で数える（`[...value].length`）。サロゲートペアの絵文字も 1 文字。
  3. **`validate`**（値が空でなく、文字数チェックも通ったとき）: 戻り値が `null` 以外なら
     `2行目: 「メール」が不正です（メールアドレスの形式ではありません）`。

> 優先順位に注意: 同じセルで文字数エラーと `validate` エラーの両方が起きうる場合、**文字数エラーが優先**され `validate` は走らない。

## よく使うバリデータ（ビルダー）

`validate` に毎回正規表現を書かなくて済むよう、よく使うチェックを 同じフォルダの `validators.ts`
にビルダー関数として用意している（バレル `csv-json` からも re-export）。いずれも `ColumnValidator`
を返し、`ColumnSpec.validate` にそのまま渡せる。メッセージは第 1 引数で差し替えられる。

| ビルダー                 | 説明                                               |
| ------------------------ | -------------------------------------------------- |
| `zenkaku(msg?)`          | 全角を含む（半角の混在は許可。半角だけの値は弾く） |
| `hankaku(msg?)`          | 半角のみ（印字可能 ASCII・半角カナ）               |
| `zenkakuKatakana(msg?)`  | 全角カタカナ（＋長音符）                           |
| `hiragana(msg?)`         | ひらがな（＋長音符）                               |
| `numeric(msg?)`          | 半角数字のみ                                       |
| `email(msg?)`            | メールアドレス形式                                 |
| `oneOf(allowed[], msg?)` | 決められた候補のいずれか                           |
| `pattern(re, msg)`       | 任意の正規表現                                     |
| `combine(...validators)` | 複数を順に適用し最初のエラーを返す                 |

**「全角 N 文字」のような長さの制約は、文字種のバリデータと `minLength` / `maxLength` を組み合わせて表現する。**

```ts
import { zenkaku, zenkakuKatakana, email, numeric, combine, hankaku, pattern } from "@/utils"

const columns: ColumnSpec[] = [
  // 全角カタカナ・ちょうど 4 文字（文字種は zenkakuKatakana、長さは min/max）
  {
    label: "フリガナ",
    key: "kana",
    usage: "required",
    minLength: 4,
    maxLength: 4,
    validate: zenkakuKatakana(),
  },
  // 全角を含み 10 文字以内（半角の混在は許可。例「第1開発部」）。
  // 文字種を問わないなら validate を付けず maxLength だけにする。
  { label: "表示名", key: "displayName", usage: "optional", maxLength: 10, validate: zenkaku() },
  { label: "メール", key: "email", usage: "required", validate: email() },
  { label: "年齢", key: "age", usage: "optional", validate: numeric() },
  // 複数条件（半角 かつ 郵便番号形式）
  {
    label: "郵便番号",
    key: "zip",
    usage: "optional",
    validate: combine(hankaku(), pattern(/^\d{3}-\d{4}$/, "郵便番号の形式ではありません")),
  },
]
```

> 文字数チェック（`minLength` / `maxLength`）は `validate` より先に走るため、同一セルでは
> 文字数エラー → `validate` エラーの順で判定される（先に失敗した 1 件のみ表示）。
> `zenkaku()` は「全角を含めば通す（半角混在OK）」ので、厳密に全角のみへ縛りたい場合は
> `pattern(/^[^\x20-\x7E｡-ﾟ]+$/, "全角のみで入力してください")` を使う。

## 出力

- `usage === "unused"` の列は出力から**項目ごと削る**。
- 出力のキー順は**入力の列順ではなく列定義（`columns`）の順**に組みなおす。
- 形式ごとの出力:
  - **`json`** … `JSON.stringify(rows, null, 2)`（2 スペースインデント）。
  - **`csv`** … papaparse `unparse`（カンマ区切り）。行区切りは `\r\n`。値にカンマ・引用符・改行を含む場合は自動で引用符囲みになる。
  - **`tsv`** … 同上でタブ区切り。

## 日本語の入力について

貼り付けるのは主に Excel・Web ページ・メールからのコピーを想定している。確認は `japanese.test.ts`。
**文字の変換（全角 → 半角・正規化）はしない**。入力のままの文字で検査し、合わなければエラーにする。

| 入力                                                 | 扱い                                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------------------- |
| Excel のコピー（タブ区切り・行末 CRLF）              | そのまま読める。セル内の改行（Alt+Enter）は引用符ごと 1 つの値         |
| UTF-8 の BOM（`U+FEFF`）付き                         | 先頭の項目名を読み違えない（前後の空白として取り除く）                 |
| 全角スペース・ノーブレークスペース                   | 前後は取り除き、途中は残す。全角スペースだけのセルは空、だけの行は空行 |
| ゼロ幅スペース（`U+200B`。Web からのコピーで混じる） | **取り除かない**（値に残る）                                           |
| 全角の読点「、」・カンマ「，」                       | 区切りにならない（値の一部）                                           |
| 全角の引用符「“”」                                   | 引用符として扱わない（中のカンマは区切りになる）                       |
| 全角数字「３０」・全角英字のメール                   | `numeric()`・`email()` で弾く                                          |
| 半角カナ「ﾔﾏﾀﾞ」                                     | `zenkakuKatakana()` で弾く（`hankaku()` は通す）                       |
| フリガナの全角スペース・中点「ヤマダ　タロウ」       | `zenkakuKatakana()` で弾く（長音符「ー」は通す）                       |
| 項目名の全角・半角の違い（「ﾌﾘｶﾞﾅ」）                | 別の項目として扱う（定義されていない項目のエラー）                     |
| サロゲートペアの漢字（「𠮷」）                       | 1 文字と数える                                                         |
| 濁点が分かれた文字（NFD。Mac 由来の「か + ゛」）     | 2 文字と数える                                                         |
| 機種依存文字（①・㈱・髙）                            | そのまま通す                                                           |

## エラー件数の上限

- エラーは合計 `MAX_ERRORS`（= 10）件で打ち切る。11 件目以降は収集しない。
- UI では、上限に達したとき見出しを「エラーが **10件以上** あります」と表示する（`errors.length >= MAX_ERRORS`）。

## 具体例

入力（列定義: 氏名=必須, メールアドレス=必須+メール形式, 年齢=省略可, メモ=不要）:

```
年齢,氏名,メールアドレス,メモ
30,山田太郎,taro@example.com,備考
```

`format: "json"` の出力（キーは列定義順、メモは削除）:

```json
[
  {
    "name": "山田太郎",
    "email": "taro@example.com",
    "age": "30"
  }
]
```
